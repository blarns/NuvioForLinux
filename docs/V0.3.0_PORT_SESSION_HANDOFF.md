### The updater channel (would have shipped broken)

The rebase took upstream's `AppUpdater.kt` wholesale. That reset `gitHubOwner`/`gitHubRepo`
to `NuvioMedia`/`NuvioMobile` and narrowed the asset filter back to `.apk` only. In the
running 0.3.0 build it offered **"0.4.2 • 38 MB"** — upstream's Android APK, which the
desktop path downloads to `~/Downloads` and hands to `xdg-open`. Every Linux user would
have been offered someone else's artifact.

Fixed by restoring the two fork constants and putting `.deb` back in
`chooseBestApkAsset`. Upstream's banner redesign, i18n'd errors and debug-preview path
are kept. `AppUpdaterPlatform.desktop.kt` was intact — only the shared config regressed.

This was the **only** fork-identity loss; the whole class is now closed:

```bash
git diff v0.2.3 HEAD -U0 | grep '^-' | grep -iE 'blarns|NuvioForLinux'
```

### The four restored features

A third round of silent drops. The doc's own 12-marker audit **passes clean** — these were
found by diffing v0.2.3 against the port at file, symbol and string-resource level.

**The sharpest discriminator: English-only string keys.** Upstream translates its strings;
the fork does not. A key present only in `values/strings.xml` and absent from every
`values-XX/` is fork-authored by construction. Use this first next time.

Restored:

| Feature | Origin commit | What was gone |
|---|---|---|
| Addon update checker | `757cf760` | 84h re-check, Updates section, toast, the `AddonRepository.initialize()` hook |
| Replace-addon-URL-in-place | `452cc79c` | ⇄ swap action, paste-URL dialog, `replaceAddonUrl` |
| Cloud audio playback | `893476cf` | both debrid providers reverted to a video-only filter |
| Collection hover-to-focus | `cf168d33` | desktop actual intact, **caller lost its 3 args** |

That last one is the doc's stated failure mode exactly: `restImageUrl`, `hoverImageUrl` and
`hovered` all have defaults, so dropping them from the call site compiled clean and left the
feature dead.

Also removed six upstream issue/PR bots the rebase reintroduced (three on a daily cron, one
on `issues: opened`). `android-release.yml` deliberately left — dispatch-only, cannot fire
unattended.

**Not drops, verified:** `desktopMain` is 100% intact (all 90 files, every top-level
declaration). `P2pSettingsPage.kt` was already dead code in v0.2.3 — the live P2P UI is in
`PlaybackSettingsPage.kt`. `p2pFilename`/`p2pSourceHints` were fork aliases; the port uses
upstream's `behaviorHints.filename`/`sources`. `AddonStreamWarmupRepository` and
`hideCatalogUnderline` are upstream code upstream itself removed. The `Nuvio*`-prefixed
`core/ui` files were renamed by upstream, not lost.

## The isDesktop bug

**The doc's verification item #1 fails without this fix.**

`73b0ab15 port: restore the desktop settings rows lost in the rebase` landed the fork's six
Linux desktop rows *inside upstream's `if (isIos)` block*, under its "iOS AUDIO OUTPUT"
heading. `isIos` is false on desktop, so **none of them render**: Audio output, Subtitle
appearance, System tray icon, Show menu bar, Discord Rich Presence, VA-API. On iOS they
would have rendered PulseAudio/ALSA/JACK and a system-tray toggle.

v0.2.3 gated them `if (isDesktop)` under a "Linux desktop" heading. The fix restores that,
leaves upstream's iOS audio-output row where it belongs, and moves the two dialogs out of
the `SettingsGroup` to section level (where v0.2.3 had them). `isDesktop` import added.

**Marker auditing cannot catch this.** Every symbol and string the handoff doc checks for was
present and correct — just behind a branch that never runs on the target platform. It was
found by walking Settings → Playback in a running build and seeing the rows absent.

## Verified working in a real run

The build had never been run by a human. It has now — `./gradlew :composeApp:run`, Linux
Mint Cinnamon / X11, 1920x1200.

- **Builds and packages.** `composeApp:packageDeb` → `nuvio_0.3.0_amd64.deb` (6m26s).
- **Main screen loads.** Profile picker → home renders with Continue Watching, Streaming
  Services, Discover. **No `CatalogRoute`/NavType crash** — the v0.1.25 class of bug is absent.
- **Settings shows Version 0.3.0 (106).**
- **MPRIS registers.** `playerctl -l` lists `nuvio`.
- **Window geometry.** `DesktopWindowGeometry: opening 1920.0x1142.0dp screen=1920.0x1160.0dp
  scale=1.0 fullscreenSupported=true` — restored-geometry path, coerced within screen.
- **Subtitle rendering + P2P sections** render and are populated.
- **System tray works.** Closing the window hid the app to tray with the process alive.
- **All six "Linux desktop" rows render** after `f537e1b3`, under their own heading, with
  the iOS row left in the iOS section. Screenshotted.
- **Audio output dialog** opens: Auto (default) ✓ / PulseAudio / ALSA / JACK.
- **Subtitle appearance dialog** opens with all four groups (size / colour / background /
  outline) and the current selection ticked in each.
- **The rows are wired, not just drawn.** Toggling *Show menu bar* wrote
  `menuBarEnabled=true` to `nuvio_machine.properties` **and** the native Playback menu
  strip appeared immediately — `PlayerSettingsRepository` → `Main.kt:157` round-trips live.
  (Toggled back to `false` afterwards, the user's original setting.)
- **Clean-profile first-run sizing (issue #4).** `XDG_CONFIG_HOME=$(mktemp -d)` →
  `opening 1728.0x1044.0dp screen=1920.0x1160.0dp scale=1.0 fullscreenSupported=true` —
  exactly 90% of the usable screen. `XDG_CONFIG_HOME` *is* honored by
  `DesktopStorage.resolveAppDataDir()`, so the doc's check #5 is valid as written.
- **The doc's own 12-marker audit passes** against `HEAD` (all counts equal v0.2.3). Its
  duplicate `load|save` check reports one hit —
  `TraktStorage.desktop.kt` — which is a **false positive**: three separate objects in one
  file, each with its own `loadPayload`/`savePayload`. The check is naive about scope.

server-side expired. The v0.1.23 error classifier should say *why*, which is itself a
verification datapoint for the port.
