# v0.3.0 upstream port — verification handoff

Written for whoever tests the 1:1 upstream port before it ships (including a terminal Claude Code
session running on the maintainer's machine). Branch: `port/finish-inversion`. Target: release by
2026-08-10.

## Why this document exists

The port rebases this fork's desktop layer onto ~1,277 upstream commits. That rebase **silently
drops fork-only code**: nothing fails to compile, because the dropped code's only callers are
dropped along with it. Four rounds of losses have been found this way, each after the previous was
believed complete — the fourth found thirteen, including two blockers that made card rows
unscrollable by mouse and the player controls dead. **Assume more is missing until checked.**

The build has never been run by a human. It compiles, the shared metadata target compiles, and it
packages — none of which proves the UI works.

## Fast structural checks

Run from a terminal — these need no UI judgement.

```bash
# 1. Startup diagnostic: screen size, scale, whether AWT can do real fullscreen
./Nuvio-0.3.0-x86_64.AppImage 2>&1 | grep DesktopWindowGeometry

# 2. Window actually sized to the screen (compare against your resolution)
xdotool search --name '^Nuvio' getwindowgeometry

# 3. Fullscreen genuinely resizes the window (press F in-app, then re-run #2)

# 4. MPRIS
playerctl -l && playerctl metadata && playerctl status

# 5. Clean-profile first-run test — window sizing only reproduces without saved geometry
XDG_CONFIG_HOME=$(mktemp -d) ./Nuvio-0.3.0-x86_64.AppImage
```

Expected from #1 on a 1920x1080 screen with no panel:
`opening 1728.0x972.0dp screen=1920.0x1080.0dp scale=1.0 fullscreenSupported=true ...`

## Regression baseline

v0.2.3 is the shipped, known-good build. When something looks wrong, run the same check against
the v0.2.3 AppImage before filing it against the port — the two can be run side by side, and a
difference is far more informative than an absolute judgement.

## Known-unresolved, do not treat as port regressions

- **Issue #4 fullscreen half (sway).** Compose implements fullscreen on Linux as
  `GraphicsDevice.setFullScreenWindow`, which delegates to AWT's X11 backend; that backend matches
  the window manager against a hardcoded list that does not include sway. Unconfirmed, and **not
  reproducible on Cinnamon** — it needs the original reporter.
- **End-of-playback blink.** Pre-existing, deliberately left alone. Worth measuring rather than
  eyeballing: capture with `ffmpeg -f x11grab` over the final seconds and check per-frame
  luminance, which turns it into a frame number instead of an impression.
- **Triple-click on Cinnamon.** Nuvio installs no global input hooks (verified: no
  `addAWTEventListener`, `KeyboardFocusManager`, `Robot`, `setAlwaysOnTop`). Test with an external
  USB mouse to separate touchpad configuration from the app.

## How the audit was done — repeat it if the branch is rebased again

**Marker presence is not enough.** The first three rounds compared symbol *existence* between the
port and v0.2.3 and came back clean while thirteen fork features were dead. Every one of them was
present and compiling; what was missing was the *caller*. A fourth round comparing call-site counts
found them all:

```bash
for m in onRightClick rowWheelScroll RowScrollArrows suppressSurfaceTapGestures \
         playerSurfaceMouseActivity registerPlaybackFlushCallback provideSessionManager \
         VolumeSlider onVolumeChange RegressionGuardNearZeroMs ExternalOpenRequestStore \
         currentPluginPlatformTags fetchCatalogViaAnon avatarImageFailed; do
  printf '%-32s v0.2.3=%-3s HEAD=%s\n' "$m" \
    "$(git grep "$m" v0.2.3 -- composeApp/src | wc -l)" \
    "$(git grep "$m" HEAD    -- composeApp/src | wc -l)"
done
```

Counts must match, and where they differ you must be able to name why. Two legitimate deviations
exist today: `onRightClick` is 11 vs 12 because the episode card now inherits it through
`posterCardClickable`, and `suppressSurfaceTapGestures` / `provideSessionManager` gained one actual
each because upstream has iOS source sets the fork did not.

**Then check reachability, not just presence.** A restored call site inside the wrong platform
branch passes every count and still renders nothing — this happened once already, with six desktop
settings rows spliced into an `if (isIos)` block. Audit the gates directly:

```bash
grep -rn "isIos" composeApp/src/commonMain --include=*.kt   # nothing desktop-only may appear here
grep -n  "isDesktop" composeApp/src/commonMain/kotlin/com/nuvio/app/features/settings/PlaybackSettingsPage.kt
```

Comparing marker strings is still worth doing as a first pass — it catches whole-file drops that the
compiler cannot:

```bash
git archive origin/port/finish-inversion composeApp/src | tar -x -C /tmp/port
for m in NuvioBlockingDispatcher SOURCE_TIMEOUT_MS PLUGIN_FETCH_TIMEOUT_MS \
         consumeAfterEpisodeIfArmed menuBarEnabled trayIconEnabled \
         discordRichPresenceUnavailableReason invalidatePlayerEngineConfig \
         loadAudioOutput DesktopWindowGeometry subtitleAppearanceSummary AudioOutputDialog; do
  printf '%-38s port=%-3s rel=%s\n' "$m" \
    "$(grep -rl "$m" /tmp/port 2>/dev/null | wc -l)" \
    "$(git grep -l "$m" v0.2.3 -- composeApp/src 2>/dev/null | wc -l)"
done
```

Counts must match. A zero on the port side with a non-zero release side is a silent drop.

**When resolving cherry-pick conflicts into the port, always check for duplicates afterwards** —
the port already carries some re-applied fork code, so taking "theirs" wholesale can double-declare
it. This bit once already:

```bash
grep -oE 'fun (load|save)[A-Za-z]+' <file> | sort | uniq -d   # must be empty
```

## Release procedure

Manual dispatch of `.github/workflows/release.yml`. Dry run first (`dry_run=true`) — it builds both
artifacts without tagging. `version` must equal `MARKETING_VERSION` in
`iosApp/Configuration/Version.xcconfig`. Publishing requires `target_commitish: cmp-rewrite`; the
in-app updater only shows releases matching its channel branch, so the port must be merged to
`cmp-rewrite` before a real release run.
